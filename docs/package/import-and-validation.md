# Secure import and validation pipeline

## Staged workflow

Acquire a user-selected local archive or explicitly approved download; verify outer size/hash when supplied; inspect central directory and manifest without trusting them; validate metadata/compatibility; extract into a new private staging directory; stream-check every entry; validate decoded resources in restricted workers; commit an immutable package; then offer Apply separately.

Do not overwrite an existing package tree in place. Use content-addressed staging and a final atomic move. A crash or cancel leaves no half-installed active package. Clean abandoned staging directories only after verifying they belong to the app.

## Archive attacks

Reject absolute paths, traversal, backslashes, drive letters, UNC paths, alternate data streams, reserved names, duplicate entries, case collisions, ambiguous Unicode encodings, symlinks, hard links, devices, and encrypted/multipart archives. Do not trust only the central-directory sizes; local records and streamed bytes must agree with policy.

Create files using exclusive/no-follow operations relative to a trusted private directory. Validate each path component and avoid filesystem races through attacker-controlled junctions or links. Recheck actual final locations where the platform lacks equivalent safe relative-opening primitives. Never extract to a user-selected arbitrary directory during import.

Set counters for compressed bytes, expanded bytes, entries, individual size, CPU time, and nesting. Large compression ratios are suspicious, but ratio alone is not the security boundary; hard actual-output limits and cancellation are. ZIP helper methods are building blocks, not a complete package policy. [S35](../research/source-register.md#s35)

## Parser and media validation

Bound JSON before parsing; reject duplicate keys and excessive nesting. Validate manifest and scene schema, then semantic graph and asset references. Fonts and media are untrusted binary parsers. Decode dimensions before allocating where possible, enforce total decoded limits, and use isolated workers with timeout/resource restrictions. The image crate's limits have implementation considerations; do not treat one decoder flag as a universal sandbox. [S28](../research/source-register.md#s28)

FFmpeg can access protocols and nested resources. Restrict demuxers/protocols to the supported local feature set, pass approved handles/custom I/O, and prevent arbitrary local path traversal by nested playlists. A `file` protocol allowlist alone does not stop reading other local files. [S32](../research/source-register.md#s32)

No thumbnail decoding should happen in the main UI process before trust checks. Missing previews can be generated by the restricted engine after validation.

## User experience

The pre-import panel shows name, claimed author, source kind, size, license, required/optional capabilities, compatibility, and trust status. Unsigned local packages are allowed after safety validation; they are labelled unverified, not automatically malicious.

Conflicting ID/version with a different hash is a conflict, not a silent replacement. Permit storing a separately identified local variant after confirmation. Same bytes imported twice should deduplicate without re-decoding everything.

## Failure handling

Return a stable error code, safe field/path location, and actionable description. Do not echo arbitrary embedded HTML into the UI. On cancel, revoke worker handles, remove staging, keep existing assignments untouched, and avoid partial library indexing.

Proposed negative cases are listed in [test vectors](examples-and-test-vectors.md); they are not claims that a native importer has already been implemented.
