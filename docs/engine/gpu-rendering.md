# GPU glyph rendering and compositing

## Render design

Rasterize glyph masks into an atlas, upload a compact cell buffer, and draw instanced quads. The shader derives the cell position from instance index or explicit layout data and samples the matching glyph mask. A full scene is not thousands of UI text widgets.

CPU cells can use a 12-byte explicit record, while GPU buffers may use padded/aligned records such as 16 bytes according to the selected shader/storage layout. Never assume Rust struct layout matches WGSL. Add layout-size and roundtrip tests.

### Bounded presenter implementation (RND-001)

`ascii-render` consumes a validated `AsciiFrame`, the immutable FNT glyph table, an explicit core budget and cancellation token, and a device/queue supplied by the host. The renderer is bound to that table and device; replacing either requires a new renderer. Frame table identity, exact row-major count, glyph indices, checked sizes, work, atlas dimensions, storage binding size and enabled device limits are checked before GPU allocation or upload. Core errors remain typed; unsupported target formats and device limits have separate renderer errors.

Core `AsciiCell` contains a glyph index and straight sRGBA8 foreground/background (12 bytes on the supported Rust layout). It is not uploaded by transmutation. The presenter explicitly serializes each shader record as four little-endian 32-bit words at byte offsets 0, 4, 8 and 12: glyph, packed RGBA foreground, packed RGBA background, and flags. Flags are currently zero because core cells have no flags. WGSL declares `@align(16)` on the first member, giving 16-byte alignment and array stride; the renderer-owned shader is `ascii-presenter-2`. Tests cover Rust layout/offsets, explicit conversion, and an optional real-GPU roundtrip including a deliberately incorrect 12-byte stride.

The R8 coverage atlas is built from cell-clipped FNT masks, placed in one-pixel zero-coverage guard borders, tiled under `max_texture_dimension_2d`, and sampled with integer `textureLoad` using the glyph's interior pixel origin and cell extent. The declared sampling mode remains unfiltered integer loads; padding is reserved for safe future filtering and does not claim fractional-DPI filtered rendering. Grid cells cover the target proportionally without snapping or animation-dependent rounding. Input sRGB is decoded to linear, coverage modulates foreground alpha, and foreground is composited premultiplied over a premultiplied background. The baseline accepts only `Rgba8UnormSrgb` and `Bgra8UnormSrgb` single-sample 2D render attachments; the host is responsible for choosing a compatible surface alpha/compositing mode.

The presenter renders background and glyphs as two instanced draws in one render pass directly into the host target. It creates no layer, postprocessing, bloom, trail, full-resolution intermediate or readback target, and it accepts no package-provided WGSL. Effects and higher-level composition are not implemented by this baseline. Exact cell content and target identity/revision determine the static cache; unchanged content on an undamaged target skips acquisition, upload, submission and draw, while damage invalidation redraws using existing GPU inputs. A host-reported surface issue takes precedence over this cache hit and invalidates the last presentation.

RND-002's current integration adds a one-pixel transparent guard around each immutable FNT glyph mask and includes the expanded tile dimensions in device-limit, byte-budget and upload-staging preflight. The renderer remains bound to one `Arc<GlyphTable>` and one host device. It does not yet own a cross-renderer atlas cache: preview and wallpaper must share one renderer instance to reuse its atlas. Font/settings generation replacement, cross-renderer cache budget/eviction, and device-migration retirement are not implemented or accepted by this slice. Same-device cache reuse, filtered fractional-scale goldens, and physical-device migration lifetime remain unverified.

Raster preflight accounts for the logical R8 texture plus one explicitly allocated `MAP_WRITE | COPY_SRC` staging buffer. Its row pitch is the atlas width rounded up to wgpu's 256-byte buffer-to-texture copy alignment, multiplied by the full atlas height; the padded size is checked against the raster budget, host addressability and `max_buffer_size` before allocation. The checked per-presentation work estimate is `2 × target_pixels + 2 × tight_atlas_bytes + padded_staging_bytes + 3 × grid_cells`: two target-pixel passes, one tight-atlas pass for glyph-mask packing and another for texture copy, the padded staging size for wgpu's zero-initialization, and three cell passes for validation, cached-frame comparison, and serialization. `Budget::max_work_units` is the ceiling for this estimated-work sum, not a time target; the conservative worst-case total is checked before cache comparison or serialization, even when the unchanged-frame path later skips drawing. Glyph masks are written directly into that mapped buffer and copied to the texture in the presentation command buffer. This avoids `Queue::write_texture`'s backend-dependent hidden staging pitch, including Vulkan's device-dependent optimal alignment. The renderer retains the copy buffer until the corresponding submission has completed. Frame-budget accounting includes CPU records, retained GPU cell-buffer capacity and one wgpu cell staging copy; the upstream glyph table, input frame, host target, uniform data and backend/driver allocation overhead are separately owned or outside these logical estimates. Only one renderer submission is in flight: a subsequent changed presentation waits for it before reusing or replacing GPU resources. This bounded policy can block and is not a measured latency claim. The renderer checks cancellation during validation and CPU packing, before mapped-buffer creation and immediately before queue writes. In pinned wgpu, creating that buffer synchronously maps and zero-fills the full padded range; cancellation cannot interrupt this work inside wgpu, but is checked when atlas packing resumes. An in-progress device wait or already submitted GPU operation is not cancellable.

### Native validation and evidence status

Native GPU behavior, perceptual tolerance and timing are established only for the explicitly recorded runs below; other environments remain unverified. `cargo test -p ascii-render --test glyph_render -- --ignored --nocapture` requests a real adapter and fails rather than fabricating success if unavailable. Set `ASCIIWALL_WGPU_BACKEND` to `vulkan`, `dx12`, `metal`, or `gl` to select the backend under measurement; an unset value permits any available backend. The rights-cleared source-generated font fixture is `crates/ascii-convert/tests/support/synthetic_font.rs`, `synthetic_font(false)`, raster size 8, 8×12 cells, baseline 9, repertoire space/A/B, and pinned fontdue 0.9.3. The run prints SHA-256 of generated font bytes and shader source, the complete glyph-table fingerprint, adapter/backend/driver information, and shader revision; the evidence recorder must also supply OS build and display configuration.

The 4×4 and Balanced 240×68 test compares a CPU-generated linear-premultiplied reference to GPU RGBA8 output at one mask pixel per target pixel. Its explicit tolerance is a maximum absolute sRGBA8 channel error of 4, mean channel error at most 1, and maximum/mean perceptually weighted RGB error `sqrt(0.2126*dR² + 0.7152*dG² + 0.0722*dB²)` at most 4/1 respectively, in 8-bit code values. This inexpensive weighted metric is not CIE ΔE and the reference is computed from the pinned masks, not a separately approved image asset. Tolerance and results must be reviewed on every claimed backend.

One observed **offscreen Vulkan** run used Windows 10 build 26300 x64, an NVIDIA GeForce RTX 3050 6GB Laptop GPU, NVIDIA driver 595.97, and a Rust 1.100.0 debug build. With `ASCIIWALL_WGPU_BACKEND=vulkan`, `cargo test --locked -p ascii-render --test glyph_render -- --ignored --nocapture --test-threads=1` passed five tests. The 4×4 and 240×68 goldens each had maximum absolute channel delta 1; their mean channel deltas were 0.0130 and 0.0109, respectively. For 100 warmed 240×68 redraws at 1920×816, host wall-time p95 including device completion was 2,995 µs in this single run. The shader revision was `ascii-presenter-1`, shader SHA-256 `f75bd47143b935eee6780247ed680d1f2d3749c2ea403705b77969462f7baba9`, synthetic-font SHA-256 `c90ae34f722cdf8d9bc9ee9242fe6c54961bf1e123a999f59290e433666dbef3`, and glyph-table fingerprint `4ddc3a1585b233278e7050a05eb95b777916375d3e619efb8c76cbd85db648e0`. Display configuration was not recorded; the run did not exercise a native display surface.

A later local rerun, reported in issue #123, used the same offscreen Windows/Vulkan setup and passed all six `glyph_render` scenarios, including the outline-font, invalid-frame/recovery, padded-atlas budget/copy, and shader-layout cases. It reported maximum absolute channel delta 1 for both the 4×4 and 240×68 goldens and a single-run host p95 of 2,759 µs including GPU completion. The issue report documents the same shader and base-font SHA-256 values listed above. The earlier five-test run's means and 2,995 µs p95 remain specific to that earlier run; no later-run mean delta was reported.

An exact-head evidence update for `d6b7db23678b29abe17bf39c5d9d15d55b1ee0f9` in issue #123 comment 7069590534 records an offscreen Windows/Vulkan run of 100 warmed 240×68 redraw samples with host wall-time p95 including GPU completion of 10,264 µs; the provisional 4 ms target was not met. The update also says the earlier same-head 3,151 µs result (comment 7064367293) was not reproduced under controlled-identical CLI scheduling. These are distinct single-run results; neither establishes a regression or a universal performance result.

These offscreen measurements are limited to one non-reference machine and do not establish a reference-machine result, universal 4 ms p95, support for other adapters/backends, native desktop presentation, or application integration. Native surface-loss/recovery, actual device-loss recovery and native wallpaper presentation remain unverified; manually signalling device loss in an offscreen test does not establish those behaviors. This repository contains the borrowed surface seam but no native surface-owning host or deterministic native surface-loss injector, so the native surface-loss acceptance criterion is blocked and this PR must remain draft until an actual host-surface recovery run supplies that evidence.

The ignored timing procedure reports the p95 host wall time of 100 warmed 240×68 redraws at 1920×816, including GPU completion, and whether it met the provisional 4 ms target. It is not a GPU timestamp or end-to-end application benchmark. To establish native recovery on each named OS/build, GPU/driver, backend and display configuration, a host test must configure and present an actual native surface, confirm repeated unchanged calls issue no uploads/submissions/draws, induce a genuine native surface loss or outdated condition, pass the host-observed status on the unchanged scene, then reconfigure or replace the surface, advance its generation and demonstrate a successful redraw. Also exercise acquisition-reported loss/outdated on a redraw, resize/minimize, damage, migration and actual compositor transparency. Record the real host events and outcomes; manually supplying a status or testing device loss on an offscreen texture does not prove native surface recovery. Reference-machine p95 and visual results require their own recorded runs.

### Host target and pacing contract

The host selects adapter, supported features, surface format/present mode and alpha mode, creates/configures the surface, and provides the matching device and queue. A `RenderTarget` borrows that surface or a host-created texture. Its caller assigns a target identity and advances the revision after any damage, external write, resize or reconfiguration; identities and revisions must not be reused for different target contents. For a surface, `RenderTarget::surface` also takes an `Option<RecoverableReason>` snapshot of the host's current surface status: pass `Some(SurfaceLost)` or `Some(SurfaceOutdated)` when reported by the host, including on unchanged frames, and construct each target with the latest status. A reported issue clears the static presentation cache; after resolving it, use `None` and the new generation to redraw. The host wires its device-lost callback to `DeviceStatus::mark_lost`, and handles replacement devices and surfaces. The renderer does not install or override the host callback.

`Presented` means commands were submitted and, for a surface, `present()` was called; it is not proof of compositor display or completion. `Skipped` distinguishes zero size and unchanged content. `Recoverable` distinguishes timeout (paced retry), lost/outdated surface (host reconfiguration or replacement), and signalled device loss (new device and renderer). Surface out-of-memory is an error. A suboptimal acquired frame is submitted and returned as such for host action. Acquisition-reported surface errors are observable only when a redraw acquires a frame; if the host receives no independent loss/outdated notification while a scene remains static, loss is not autonomously detected. Do not probe by repeatedly acquiring and discarding unchanged frames: pinned wgpu-hal 0.19.5's Vulkan discard path does not release acquired swapchain images, so that can exhaust the swapchain. Cancellation or device loss after a successful acquisition can also discard that frame; because the return value does not say whether acquisition occurred, the host must reconfigure after such an interrupted surface call before relying on that surface again. Asynchronous wgpu validation/device failures still require the host's error/loss handling; the synchronous API cannot certify a completed GPU operation.


## Passes

The implemented baseline consists only of background fill and glyph rendering, using two instanced draws directly into the borrowed target. Layer composition and post-processing are not supported by this presenter and allocate no resources; any future effects must be explicitly requested and allocate only their bounded required resources. Static scenes keep cached resources and only redraw after invalidation. The presenter creates no bloom, trails, full-resolution intermediate buffers, or readback targets.

The planned shared engine is intended for both wallpaper and editor preview; those host integrations are not provided by the presenter alone. A preview may use a smaller grid or quality setting for responsiveness, but it must disclose that difference and offer a final-quality preview.

## Resource ownership

The host owns the native surface and its lifetime and queries surface formats, present modes and adapter capabilities. The presenter checks enabled device limits. Select conservative supported defaults; do not assume all backends offer the same capabilities. The host must handle resize, zero-sized/minimized surfaces, lost/outdated surfaces, GPU device loss, and monitor migration explicitly. [S24](../research/source-register.md#s24)

Avoid creating a graphics device for every frame or slider change. Share immutable atlases where compatible. Across physical GPUs, share semantic frame data rather than assuming textures can be shared trivially.

## Color and sampling

Use mask coverage consistently and avoid double-applying gamma. Filtered atlases need padding to prevent adjacent-glyph bleeding; the current integer-load baseline does not filter between masks. Pixel-snapped layouts can improve legibility; fractional scaling needs a deliberate policy rather than rounded positions that jitter each frame.

A cell can show foreground and background colors. Transparent layering requires premultiplied-alpha rules shared with the compositor. Unicode symbols are glyphs in the engine's table, not terminal escape sequences.

## Presentation and power

Cap render frequency independently of display refresh. A 144 Hz display should not force a slow ambient scene to simulate at 144 Hz. Request redraw only for deadlines or invalidations. Use compositor feedback/present pacing where available but keep a robust monotonic scheduler. Do not busy-wait for frame deadlines.

## Fallback and validation

Text export and a static CPU rasterizer are separate capabilities, not fallbacks supplied by this presenter. A missing GPU does not imply animated software rendering at acceptable cost. A host that implements a fallback must report explicitly whether it selected static wallpaper or preview-only mode.

GPU golden tests use perceptual tolerances and known fonts; CPU character-grid tests can use exact results under a pinned implementation. Capture device/backend and shader versions with benchmark evidence. User packages cannot submit arbitrary WGSL in the stable format.

## Host-native presentation bridges

A shell-owned QML/GJS background is not automatically a native wgpu surface. Such adapters may present bounded offscreen frames or a compact glyph grid through host-native drawing. Treat these as separately tested presenters implementing the same visual contract, not as evidence of zero-copy cross-API texture sharing.
